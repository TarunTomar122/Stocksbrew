# design
- Use lucide-animated icons consistently across the entire app. Confidence: 0.85
- Aim for premium feel with clear visual hierarchy, avoid too many cards/card-in-card layouts. Confidence: 0.80
- Make clickable content obvious through affordances like hover states and cursor changes. Confidence: 0.75
- When redesigning a page, derive its visual language (headings, colors, border radius, font weights) from the app's established reference pages (homepage, explore) instead of inventing new styles. Confidence: 0.85
- The GitHub repo OpenLabs-so/oa-design is the canonical design-system reference for the app redesign ("the design that we were supposed to make, the rules and stuff"; "the GitHub repo from which we are taking their design inspiration and design ideas"); consult it when in doubt about design decisions. Confidence: 0.9
- Every redesigned page must be fully responsive on mobile. Confidence: 0.8
- UI controls must have an unmistakable selected/active state; when a control's active state is hard to see, revert to the earlier version the user liked (e.g. Gainers/Losers pills with primary-tinted fill) rather than iterating on the disliked one. Confidence: 0.8
- Keep numeric data (price, percent, scores) stacked vertically in table/list rows and aligned horizontally across sibling stat blocks (e.g. 52-week range vs RSI sliders on one line); misaligned or cramped numbers read as broken. Confidence: 0.75
- Section titles and descriptions should be large enough to carry hierarchy (H2 ~26px+/4xl, sub ~17px); user flagged undersized title/description type as a defect. Confidence: 0.7
- Preserve existing design: never destructively rewrite established pages (especially the home page and header) or delete the user's visual work as a side effect of a change — the user reacts strongly when existing design is lost or altered unintentionally ("I lost a lot of my design and the header is different. The home page is cooked."). Confidence: 0.65
- Use one blue CTA accent as the app's color discipline rule. Confidence: 0.85
- Prefer font weights ≤500; avoid bold/heavy weights. Confidence: 0.85
- Use tabular-nums for all numeric data display. Confidence: 0.85
- Freemium value stack: show enough free data that users feel they are getting so much value they need Pro. Confidence: 0.9
- Cut redundant UI rather than keeping both mechanisms: when a compact per-row control already does the job (e.g., the one-tap alert bell on each book row), remove the dedicated section — the user had the whole alerts plate deleted because "that big list adds nothing". Confidence: 0.7
- Signed-out views must demonstrate the product, not describe it: render a realistic sample book with answer lines plus suggested picks with one-click Track buttons, where sign-in happens as a side effect of the action; a bare descriptive signed-out page reads as broken. Confidence: 0.7
