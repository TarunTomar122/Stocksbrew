# workflow
- Explore design direction with throwaway mock-data prototypes and multiple layout variants, then converge on a winner and delete the prototype when building the real page. Confidence: 0.7
- When the user cites external references (design repos, marketing books), research them directly and map their principles onto existing codebase patterns before proposing a build. Confidence: 0.85
- Build the full implementation in one pass first, then let the user review visually and iterate; don't stall asking for plan approval before coding ("just start building... build the entire thing and then I will tell you how good or bad it is looking"). Confidence: 0.85
- Operate fully autonomously once a task is underway: user has granted full edit permissions and does not want to be asked for permission or mid-task confirmation — push the job through to completion ("Do not ask for permissions again. Continue the work.", "finish the job"). When the user signals time pressure ("Please finish this task ASAP"), cut overhead: skip optional polish and long explanations, drive straight to a finished state. Confidence: 0.9
- After the user reports broken or regressed work, stop and explain what was changed and what the current state is before touching any more code — the user explicitly asked "Can you tell me before you touch any code?". This is an exception to the autonomy preference, not a general mid-task confirmation request. Confidence: 0.75
- When the user declares an issue fixed, drop it immediately — no further verification, root-cause hunting, or post-mortem — and resume the primary task ("I fixed the issue myself... Do not worry about the issue. The issue is fixed."). Confidence: 0.8
- Keep sessions anchored on the user's product/frontend goals; environment and toolchain debugging is a means, not the deliverable — time-box it, and if it stalls the user would rather resolve it themselves and have the agent refocus on the main build. Confidence: 0.65
- Don't touch or restart the user's running dev server; verification is typecheck/lint/vitest only, and if a preview is ever needed use a separate port instead. Confidence: 0.7
- Multiple agents work concurrently in this repo; leave other agents' files and failing tests alone — don't fix, revert, or "clean up" work that isn't yours ("those are other agents' work, I'll leave them alone"). Confidence: 0.75
- When several tasks remain, complete them sequentially and visibly — announce each step, finish it, then move to the next ("Please finish all of the tasks step by step", "Finish this work please in a step-by-step way"), and resume automatically after interruptions or errors ("continue"). Confidence: 0.75
- When the user explicitly switches to plan-only mode ("You just tell me exactly what all you want to do... Just tell me, don't do it"), stop executing immediately and describe every intended change in maximal detail instead — no edits, no tool runs — until they say go. This is an explicit override of the default build-first autonomy, not a request for a brief summary. Confidence: 0.8
